## Bugs and robustness issues requiring review

1. **Mean tests use the median test-selection lists (cell 100).** Only `df_median_proximity` is checked in cell 93; both mean and median tests use those lists. This can select an inappropriate test for mean scores. Left unchanged in both notebooks because correcting it could alter reported results. No replacement assumption checks were run.
2. **Treatment inference silently labels every non-`T` sample untreated (cells 31/70).** Missing or unexpected identifiers are not checked, and the saved `obs` output also contains a `treatment_status` field. Verify agreement with study metadata before any rerun. The prefix mapping remains unchanged.
3. **Result parsing can hide or misidentify data (cell 111).** Originally missing folders yielded an empty table, while `KeyError` files were silently skipped. The extracted loader reports these failures. Splitting pairs at the first underscore and treating filename stems as unique FOV IDs are retained assumptions: verify compound gene names and uniqueness across samples against actual SCOTIA outputs. Those files were not supplied separately.
4. **Empty and degenerate inputs are incompletely handled.** No proximity records cause `pd.concat` to fail (cell 80); empty gene lists or constant-gene z-scores can break clustering, and Ward linkage needs at least two samples per treatment (cells 42/46/49). The helper deliberately retains undefined z-scores rather than filling them or excluding genes. These analysis/plotting decisions were not silently changed.
5. **Assumption checks can omit or misclassify groups (cell 91).** Groups with fewer than three values are skipped; NaNs and constant data are not explicitly handled. Failed-to-reject normality is not evidence that the data are normal. The code can treat nonfinite test p-values as passing because comparisons with NaN are false. No new test-selection procedure was introduced.
6. **Broad exception handling can leave a partial pipeline (cells 119/120).** Errors are printed and some cell-type pairs are skipped. Review logs before interpreting completeness. If no pairs qualify for comparison, cell 113 writes no summary files; previous summaries in a reused output folder can therefore remain stale. This behavior is documented and retained to avoid changing result generation.
7. **Memory and repeated work remain concerns.** Pairwise FOV distance matrices are still dense. LIANA is rerun on the same full data for each target cell type, including 1,000 permutations per call. Caching, parallelism, approximate distances, and algorithm changes were deliberately not added. Sparse NaN replacement fixes the avoidable dense expression copy only.
8. **Dependency and NumPy compatibility are uncertain.** Cell 117 sets `np.Inf = np.inf` globally as an apparent SCOTIA workaround. It remains visible in the cleaned copy; the dependency's historical version must be recovered before safely removing it. The original package versions, random-state settings, and L-R resource snapshot were not recorded in a lockfile. Exact reproduction cannot be claimed from the supplied files. Synthetic tests also exposed SciPy 1.18 deprecation warnings for the original `distance_matrix` API. The dependency range excludes its announced removal in SciPy 1.20 rather than replacing the distance implementation during this preservation-focused refactor.
9. **Categorical groupby behavior is version-sensitive (cells 18/84).** The original outputs include a pandas warning about the changing `observed` default. Unobserved categorical combinations may introduce NaN rows into sample summaries. The refactor does not change those groupings; the dependency specification keeps pandas below 3. Verify missing combinations before interpreting tests.

## Scientific and statistical interpretation

These are review findings and questions inferred from the code, not new analyses or proof that the study's conclusions are wrong. No recommendations below were implemented as new methodology.

- **Biological replication:** DGE treats individual cells as observations. Cells from a shared sample or donor are not independent biological replicates, so cell-level p-values may overstate evidence for treatment differences. Proximity tests aggregate by `sample_id`, but the saved output shows a separate `donor` field; independence among samples and any matching between conditions need confirmation. The official [Scanpy DGE documentation](https://scanpy.readthedocs.io/en/stable/generated/scanpy.tl.rank_genes_groups.html) discusses the cell-independence limitation.
- **FOV independence:** SCOTIA comparisons treat each detected FOV as independent after averaging within a pair/FOV. Multiple FOVs from the same sample or donor may be correlated. Two FOVs per condition are not necessarily two biological replicates. Mann–Whitney requires independent samples; it tests distributions and is not automatically a test of medians ([SciPy reference](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.mannwhitneyu.html)).
- **Expression layer and preprocessing:** DGE and `score_genes` omit `use_raw`, while normalization modifies `.X`. If `.raw` exists, Scanpy may use a different matrix from the one just normalized. Its state was not inspected. The input's existing normalization and missing-value meaning are also unverified; NaN-to-zero conversion and repeated normalization are retained original choices. See [Scanpy's `use_raw` behavior](https://scanpy.readthedocs.io/en/stable/generated/scanpy.tl.rank_genes_groups.html).
- **Signature selection:** Genes are selected using the treatment comparison and scored on the same cells. This is exploratory reuse of data, not independent validation. A separate 90th-percentile threshold per treatment selects roughly the highest-scoring tenth of each group, potentially more with ties. It defines relative within-condition enrichment rather than a common absolute identity. The notebook mentions g:Profiler, but no enrichment output, background gene list, or separate validation was supplied.
- **Outlier removal and test selection:** IQR filtering removes samples independently within each condition before inferential testing. In small cohorts this can alter effects and uncertainty. Shapiro/Levene pretesting adds a data-dependent choice and may have limited power. These original choices are documented, not replaced with a different test or filtering policy.
- **Multiple testing:** Proximity tests use unadjusted p-values across target cell types and two summary measures. CellPhoneDB candidates use raw `cellphone_pvals < 0.05`; Connectome `scaled_weight >= 1` is an effect/score filter, not an adjusted significance threshold. Later BH correction is applied separately within each cell-type comparison and only to eligible L-R pairs. It does not establish experiment-wide error control across the whole selection pipeline.
- **Direction and weighting:** Candidate CSVs include both source→target and target→source interactions. Combining hits keeps only gene pairs; summaries and tests group by ligand/receptor, ignoring any source/target cell-type columns. This may pool biologically distinct directions. Summary mean likelihood is weighted by available result rows, while the comparison first averages within FOV; those are different summaries and should not be conflated.
- **Missing detections:** Only detected interactions in available FOVs enter the tests. Undetected interactions are not automatically scored zero, and pairs with fewer than two FOVs in either group are skipped. Differences in detection and sample composition could affect comparisons. The pseudocount `1e-9` can yield large fold changes when mean likelihoods approach zero.
- **Spatial interpretation:** The score is a sum of exponential weights, without normalization by partner abundance or tissue area. It reflects abundance and geometry as well as proximity. `radius=50` is a decay length, not a cutoff; all within-FOV pairs contribute. Comparisons omit cross-FOV neighbors and can be affected by tissue boundaries. The 0.18 µm/px instrument calibration needs verification from acquisition metadata. Identical populations would include self-interactions; the current analysis uses different focal/target populations.
- **Predicted communication:** LIANA and SCOTIA infer candidate interactions from expression and spatial information. These are not direct measurements of signaling or functional validation. Third-party methods and their underlying resources should be credited separately from the author's custom workflow ([LIANA documentation](https://liana.readthedocs.io/en/stable/), [SCOTIA upstream](https://github.com/Caochris/SCOTIA)).
